# Landing page

Frontend layout: responsive, on the breakpoints of `@syneva/design-system`'s `media` (`packages/design-system/src/media.stylex.ts`). This standalone public site is separate from the review application.

Read `DESIGN.md` in this directory before changing landing-page styling or copy. The repository-root design system governs the review application only.

The site is a static Astro app laid out in Feature-Sliced Design layers, strictly downward: `src/app` (the document shell `layouts/Document.astro`, `styles/global.css`, the runtime boot `scripts/site.ts`), `src/views` (the FSD pages layer, named `views` because Astro reserves `src/pages`: one slice per site section, `home`, `product`, `workflows`, `resources`, plus `lost` for the 404, each holding its page components, their sections and their drawings under `ui/`, and under `model/` the data they render (the agent contract) or the readers of their content collections (the FAQ, the changelog)), `src/widgets` (`navigation`, `footer`, `cta-band`, `chapter`, `page-hero`, `page-index`), `src/features` (`copy-command`, `disclosure`), `src/entities` (`site`: the site map in `model/site-map.ts`, every page by slug with its section and availability, which menus, footer, breadcrumbs, page heroes and pagers read and every internal link names its page through; `model/routes.ts` answers what it says about one route; `model/project.ts` holds the project's facts (its install and start commands, its GitHub links), and `model/icons.ts` with `ui/Icon.astro` draws its icons; `desk`: the desk's key bindings in `model/hotkeys.ts` and the address the drawings give it in `model/desk-origin.ts`), and `src/shared` (`lib/` for `sx`, `reveal`, `rich-text`, `two-digits`, `map-classes`, `part-attribute`, `ui/` for the actions, the brand, the prose blocks and the drawing kit in `ui/drawing/`). `src/pages/` holds the Astro routes (built to `dist/<route>/index.html`, plus `404.html`): each composes the document shell with its page view and owns the route's metadata. Local content lives in Astro content collections: `src/content.config.ts` declares each collection's schema and `src/content/*.json` holds the entries (the FAQ's topics, the changelog's weeks); a slice reads them through its `model/` reader, never with `getCollection` in a template. `src/middleware.ts` sets the page kind (`Astro.locals.page`: `home`, `sub` or `lost`) from the route before anything renders; the shared sections restyle by it. Cross-layer imports use the aliases `@app`, `@views`, `@widgets`, `@features`, `@entities`, `@shared` (declared in `tsconfig.json`; `layers.json` lists the layers for `astro.config.ts`, which repeats the aliases for StyleX, and for the root `oxlint.config.ts`); imports inside a slice stay relative; slices of one layer never import each other; oxlint enforces the rules on the `.ts` modules and the `.astro` components follow them by convention. Styles are StyleX, colocated in a `*.styles.ts` next to their component, with markers and variables in `*.stylex.ts` (a marker a lower layer's style reads lives in that lower layer, and the upper layer applies it); `src/app/styles/global.css` keeps only the font faces, the reset and element typography. Tokens and breakpoints come from `@syneva/design-system` (`packages/design-system`), the motion runtime from `@syneva/motion` (`packages/motion`, on Motion). Preview with `pnpm dev:site`. `pnpm build` builds the app with the rest of the workspace into `dist/`, the assets root `nextnode.toml` hands to the deploy (`assets = "apps/landing/dist"`); `public/healthz` answers the pipeline's smoke check. `integrations/linked-pages.ts` fails the build on any internal `href` or `src` in the built pages (and any site map entry) that reaches no built page or public asset. Only `public/` and the built pages deploy; the docs and the acceptance specs (`spec.json`, `navigation-spec.json`) never do.

Copy follows `PRODUCT.md`: first-person, direct, low-hype, and every claim true of the CLI today. Prototype work is labeled as such; numbers are product facts, never metrics.

## StyleX invariants

- Merging is per property and replaces the whole value: a later style with `{ default: null, … }` drops an earlier style's default for that property. Give an element that sets a property its own conditional values instead of merging a generic modifier over it.
- `stylex.when.ancestor(…, marker)` needs the marker on an ancestor, never on the element itself; the element's own states use plain pseudo-classes (`':hover'`).
- `border: 0` also resets the style and colour: write the three longhands, and restate them under the media query that zeroes them.
- Media keys are overlapping max-width ranges declared widest first, so the narrowest matching query wins (StyleX keeps the last match); a shorthand under a media query outranks an unconditioned longhand: restate the longhand under the same query.
- The CSS minifier rewrites values (`240ms` becomes `.24s`): a script that reads a token from the computed style parses its unit.

## Motion invariants

- The markup is always the finished pose. Hidden poses are StyleX styles armed by `html[data-motion]`, and the safety net shows everything after 3s if the runtime never boots.
- A drawing element opts in with `data-anim` and an optional `data-delay`; nested elements inherit the nearest delay.
- An entrance plays once. A scene pauses only its running animations while it is out of view (or the tab is hidden) and resumes them where they paused; reduced motion finishes its entrances instead, so none holds an element hidden, and pauses its loops. A scene never calls `play()` on one sitting at its end, because the Web Animations auto-rewind would restart it from its first frame and the finished element would vanish and enter again.
- An element without a box (`display: none`, a drawing's secondary words on phones) animates unseen and shows its finished pose if it gets a box later.
- `@syneva/motion` is the site's only way to Motion: the landing never imports `motion` or `motion/*` itself (oxlint rejects it). `@syneva/motion/engine` is the package's one seam onto the engine (`animate`, `inView`, `frame` and their types, for the package's own modules too), and a Motion API the site needs is exported from it first, so the engine can change without touching the site.
